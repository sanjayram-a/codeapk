# Lifetime Pro Paywall Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a one-time lifetime Pro unlock, one shared paywall, four feature gates, and Play Billing purchase/restore/refund handling to OpenCode Pocket.

**Architecture:** A `ProController` owns entitlement state and exposes `isPro`. A `PlayBillingGateway` wraps the official `in_app_purchase` plugin. One `PaywallPage` is opened by every gate. Settings shows a plan card and the idle-timeout gate. Gating is UI-level and never deletes user data.

**Tech Stack:** Flutter/Dart, Material 3, `in_app_purchase` ^3.3.1 + `in_app_purchase_android` ^0.5.5 (Play Billing 9.1), `shared_preferences`, the existing `opencode_runtime` PTY for the read-only build-tools task.

**Spec:** `docs/superpowers/specs/2026-11-13-paywall-design.md`

## Global Constraints

- Product ID is exactly `pro_lifetime`; it is a one-time non-consumable. No trial, subscription, ads, accounts, RevenueCat, or backend.
- The charged price is always Play's localized `ProductDetails.price`; never hardcode it in the UI. The founder price lives in Play Console.
- Free gates: terminal, Save to Downloads/export, per-project size breakdown, idle background run over 5 minutes.
- Build tools stay free, but only through a read-only task sheet; no interactive terminal.
- Never delete or hide existing files or settings when a plan changes. Block only the gated action. Closing live terminal sessions on a Pro revoke is the one exception, because the terminal itself is the gated feature.
- Offline grace is 7 days. A successful purchase query with no `pro_lifetime` revokes immediately; a failed query keeps cached Pro only inside the grace.
- Pending purchases do not grant Pro. Acknowledge owned purchases immediately; retry on the next launch.
- Paywall and plan copy use “Unlock” and “one-time”, never “subscribe”.
- App theme seed is `Color(0xFF3F6BE0)`; app name is `OpenCode Pocket`.
- No real Play calls in widget tests. Every test injects `FakeBillingGateway`.
- `flutter analyze` must be clean and `flutter test` must pass before the final task.

## Review Focus

These are the five failure classes the implementation and tests must cover:

1. **Offline / cached Pro:** a failed purchase query must not revoke Pro inside the 7-day grace, and must revoke after it.
2. **Refund / chargeback:** a successful query with no `pro_lifetime` must revoke Pro and persist the change.
3. **Pending / unacknowledged purchase:** pending must not grant; a purchased or restored entitlement must be acknowledged immediately and again on the next launch if needed.
4. **Price unavailable / billing unavailable:** the paywall must say so plainly, never show a fake price, and offer Retry.
5. **Secondary gate paths:** a free user must not reach downloads through the file editor, project sizes through Storage, or build tools through an interactive terminal.

Additional race: a purchase event that arrives while a slow `queryPurchases` is in flight must not be overwritten by the stale empty result. Task 1 tests this explicitly.

```dart
class FakeBillingGateway implements BillingGateway {
  bool available = true;
  BillingProduct? product = const BillingProduct(
    id: proProductId,
    title: 'OpenCode Pocket Pro',
    description: 'Lifetime Pro',
    price: '₹999',
    rawPrice: 999,
    currencyCode: 'INR',
  );
  List<BillingPurchase> purchases = const [];
  Object? queryError;
  Object? acknowledgeError;
  Completer<void>? purchasesGate;
  final _purchases = StreamController<BillingPurchase>.broadcast();
  int queryProductCalls = 0;
  int queryPurchaseCalls = 0;
  int buyCalls = 0;
  int restoreCalls = 0;
  final bought = <String>[];
  final acknowledged = <String>[];

  @override
  Future<bool> isAvailable() async => available;

  @override
  Stream<BillingPurchase> get purchaseStream => _purchases.stream;

  @override
  Future<List<BillingProduct>> queryProducts(Set<String> ids) async {
    queryProductCalls++;
    if (queryError != null) throw queryError!;
    return product == null ? const [] : [product!];
  }

  @override
  Future<List<BillingPurchase>> queryPurchases() async {
    queryPurchaseCalls++;
    await purchasesGate?.future;
    if (queryError != null) throw queryError!;
    return purchases;
  }

  @override
  Future<void> buy(String productId) async {
    buyCalls++;
    bought.add(productId);
  }

  @override
  Future<void> acknowledge(String purchaseToken) async {
    if (acknowledgeError != null) throw acknowledgeError!;
    acknowledged.add(purchaseToken);
  }

  @override
  Future<void> restore() async {
    restoreCalls++;
  }

  void emit(BillingPurchase purchase) => _purchases.add(purchase);

  @override
  Future<void> dispose() async {
    await _purchases.close();
  }
}
```

- [ ] **1.6 Implement `app/lib/pro/pro_controller.dart`.** Required behavior:
  - Constructor reads `settings.proOwned` / `settings.proLastVerifiedAt`; `_lastVerifiedAt` starts from the stored value, `_owned = settings.proOwned && _withinGrace()`, and `_status` starts `pro` when `_owned` else `loading`. This prevents an eight-day-old flag from briefly unlocking Pro on launch.
  - `initialize()` is idempotent via a cached future. Subscribe to `purchaseStream` synchronously before the first `await` so an event emitted immediately after construction is not lost, then check `isAvailable()` inside a `try/catch`. If unavailable or the check throws, set `error` (`'Google Play is not available on this device.'` or the exception message), keep cached Pro only when `_withinGrace()`, otherwise clear ownership and set `status = error`. If available, call `refresh()` (which catches its own query failures).
  - Subscribe with an `onError` handler: a purchase-stream error sets `error` and, when not already Pro, `status = error`; it must not revoke cached Pro.
  - `refresh()` is single-flight **while a refresh is in progress**: if one is running, return the same future, and clear the cached future in `whenComplete` so a later resume/Settings/paywall call queries again. It loads the product in a `try/catch`; on error set `product = null` and retain the message, but **do not return early** — the purchase query decides entitlement. Then query purchases. Capture `_generation` at the **start of the refresh** (before the product query). After the purchase query completes, whether it succeeded or threw, if `_generation` changed, discard the result entirely and return; the stream event's state wins. This covers a purchase event during either query. On a fully successful product + purchase refresh, clear `error`.
  - On a successful purchase query: set `_lastVerifiedAt = DateTime.now()`, persist it, and acknowledge every purchased/restored `pro_lifetime` purchase with `pendingCompletePurchase == true` (catch and retain an error message; do not revoke). Never acknowledge a pending purchase. If an owned/restored purchase exists, set `_owned = true`, persist `pro_owned = true`, status `pro`. If only pending exists, set `_owned = false`, persist `pro_owned = false`, status `pending`. If neither, set `_owned = false`, persist `pro_owned = false`, status `free` (this is the refund path).
  - On a failed purchase query: set `error`; if `_owned` and `_withinGrace()` keep status `pro`; otherwise set `_owned = false`, status `error`. Never clear `pro_owned` on a failed query.
  - `_withinGrace()` is `lastVerifiedAt != null && DateTime.now().difference(lastVerifiedAt!) <= const Duration(days: 7)`.
  - `_onPurchase(purchase)`: ignore other product IDs before touching state; increment `_generation`; set `_purchasing = false`. Purchased/restored: grant, persist, set `lastVerifiedAt`, clear `error`, status `pro`, then acknowledge if `pendingCompletePurchase` inside a `try/catch`; on an acknowledgement failure set `error` to the exception message but keep Pro. Pending: clear `error`, status `pending`, no grant. Canceled: clear `error`, status `pro` if `_owned` else `free`. Error: set `error = purchase.error ?? 'Purchase failed.'`, status `pro` if `_owned` else `error`.
  - `buy()`: if owned or purchasing, return. If `product == null`, set `error = "Pro isn't available right now."` and status `error`, notify, return. Set `_purchasing = true`, call `gateway.buy(product.id)`, and on throw set error/status and clear purchasing.
  - `restore()`: if purchasing, return. Set `_purchasing = true`, call `gateway.restore()` then `refresh()`, clear purchasing in `finally`, and on throw set error/status.
  - `dispose()`: cancel the subscription, call `gateway.dispose()`, guard notifications with a `_disposed` flag.

```dart
Future<bool> showPaywall(
  BuildContext context,
  ProController pro,
  ProFeature feature,
) async {
  try {
    await pro.initialize();
    await pro.refresh();
  } catch (e) {
    // Billing failures must never block the gate; the page renders the error state.
    debugPrint('Billing refresh failed: $e');
  }
  if (!context.mounted) return false;
  return await Navigator.of(context).push<bool>(
        MaterialPageRoute(
          fullscreenDialog: true,
          builder: (_) => PaywallPage(pro: pro, feature: feature),
        ),
      ) ??
      pro.isPro;
}
```
